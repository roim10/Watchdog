Watchdog

Параллельный агрегатор и монитор внешних HTTP-источников, написанный на Go.

Сервис регулярно и параллельно опрашивает список внешних HTTP-эндпоинтов (API курсов валют, погоды, тестовые источники и т.д.), кэширует результаты, хранит ограниченную историю значений по каждому источнику и отдаёт всё это через собственный REST API. Список источников можно изменять в рантайме — без перезапуска сервера.

Проект создавался как учебный pet-project для закрепления ключевых тем Go: конкурентность, обработка ошибок, работа с файлами, HTTP-сервер и клиент, JSON.

Возможности
Параллельный опрос нескольких независимых источников с индивидуальным таймаутом на каждый HTTP-запрос
Устойчивость к частичным отказам — падение одного источника не мешает получению данных по остальным
Потокобезопасное хранение текущего состояния каждого источника
Ограниченная по размеру история последних результатов по каждому источнику, с таймстампами
Фоновый опрос по таймеру, работающий параллельно с HTTP-сервером, не блокируя его
Управление списком источников в рантайме через HTTP API (добавление/удаление)
Персистентность: изменения списка источников сохраняются в файл и переживают перезапуск сервера
Подтверждённое отсутствие гонок данных (go run -race)
Стек
Go (goroutines, channels, sync.WaitGroup, sync.RWMutex, context)
gorilla/mux — маршрутизация HTTP
encoding/json — сериализация/десериализация
net/http — HTTP-сервер и клиент
Архитектура

Проект разделён на независимые пакеты, каждый со своей зоной ответственности:

Пакет	Назначение
read	Чтение и парсинг списка источников из api.txt, а также запись изменений обратно в файл
sources	HTTP-опрос одного источника с таймаутом; не паникует и не завершает программу при ошибке
registry	Потокобезопасное хранение текущего состояния каждого источника (sync.RWMutex + карта)
history	Потокобезопасное хранение истории результатов по каждому источнику, с ограничением размера
sourcestore	Потокобезопасное хранение списка источников, позволяющее добавлять/удалять их в рантайме
survey	Параллельный опрос всех источников за один цикл (горутины + WaitGroup)
httpapi	HTTP-обработчики и DTO-структуры для JSON-ответов
main	Точка входа: связывает всё вместе, запускает фоновый опросчик и HTTP-сервер
Формат конфигурационного файла

Источники задаются построчно в api.txt:

Bitcoin https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=usd
Weather https://api.open-meteo.com/v1/forecast?latitude=52.52&longitude=13.41&current=temperature_2m
JSON https://jsonplaceholder.typicode.com/posts

Каждая строка: имя URL, разделённые пробелом.

Запуск
bash
go run main.go

Сервер стартует на :8080, сразу выполняет первый опрос всех источников из api.txt, а затем продолжает опрашивать их по таймеру в фоне.

HTTP API
GET /status

Возвращает текущее состояние всех источников.

bash
curl http://localhost:8080/status
json
[
  { "name": "Bitcoin", "code": 200, "body": "{\"bitcoin\":{\"usd\":84399}}" },
  { "name": "Test", "code": 0, "body": "", "error": "dial tcp ...: connection refused" }
]
GET /status/{name}

Возвращает состояние конкретного источника. 404, если источник с таким именем не найден.

bash
curl http://localhost:8080/status/Bitcoin
GET /history/{name}?limit=N

Возвращает последние результаты опроса по источнику, с таймстампами. Параметр limit необязателен; если указан — должен быть положительным целым числом.

bash
curl http://localhost:8080/history/Bitcoin?limit=3
json
[
  { "name": "Bitcoin", "code": 200, "body": "...", "time": "2026-10-05T23:40:56+03:00" }
]

Ошибки: 404 — источник не найден; 400 — некорректный limit (не число или ≤ 0).

POST /sources

Добавляет новый источник для мониторинга. Источник сразу сохраняется и в памяти, и в api.txt — переживает перезапуск сервера.

bash
curl -X POST http://localhost:8080/sources \
  -H "Content-Type: application/json" \
  -d '{"name":"Weather","url":"https://api.open-meteo.com/v1/forecast?latitude=52.52&longitude=13.41&current=temperature_2m"}'

Ошибки: 400 — пустое имя или некорректный JSON; 409 — источник с таким именем уже существует.

DELETE /sources/{name}

Удаляет источник из мониторинга. Удаление синхронизируется и с памятью, и с файлом.

bash
curl -X DELETE http://localhost:8080/sources/Weather

Ошибки: 404 — источник не найден.

Конкурентность
Каждый цикл опроса запускает параллельный HTTP-запрос к каждому источнику в отдельной горутине; sync.WaitGroup гарантирует, что снапшот формируется только после завершения всех запросов цикла (включая упавшие по таймауту).
Общее состояние (Registry, History, SourceStore) защищено через sync.RWMutex: множественные одновременные чтения (HTTP-запросы) не блокируют друг друга, запись (фоновый опрос, POST/DELETE /sources) получает эксклюзивный доступ.
Фоновый опросчик работает в отдельной горутине на time.Ticker, независимо от HTTP-сервера.
Отсутствие гонок данных подтверждено через go run -race на нескольких этапах разработки.
Известные ограничения

Проект — учебный, и некоторые упрощения сделаны осознанно:

Нет graceful shutdown по сигналу ОС — фоновый опросчик останавливается вместе с процессом.
Нет ограничения на количество одновременных исходящих запросов — при большом числе источников возможна нагрузка на сеть.
POST /sources не поддерживает индивидуальный таймаут для нового источника.
